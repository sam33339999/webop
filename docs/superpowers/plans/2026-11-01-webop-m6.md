# webop M6（第二個 agent 與打包）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** grok 與 opencode 能同時各自操作自己的分頁群組、互不干擾；`webop` 打包成單一 SEA 執行檔，不再綁死某個 node 路徑；`webop doctor` 一次說清楚安裝與連線哪裡壞了。

**Architecture:** 四個獨立交付：(1) host 新增不開 session 的 `ping`，給 doctor 查詢 profile 與版本；(2) `webop doctor` 讀 NM manifest、包裝腳本、run 目錄並 ping 每個在線 host；(3) 現有的 ESM bundle 直接當 SEA 入口（`mainFormat: "module"`），擴充 ID 於建置時寫死；(4) 兩個 MCP client 同時操作的 e2e 與 grok 接法文件。版本升到 0.6.0。

**Tech Stack:** 同 M5；SEA 用 Node 26 內建的 `node --build-sea`（不加 postject 等新相依），macOS ad-hoc `codesign --sign -`。

**Spec:** `docs/superpowers/specs/2026-10-31-webop-design.md`（§2 G2/G5 與反目標「兩個 agent 互搶分頁」、§3 打包、§4.1、§4.3、§4.7、§6 M6 列）。前置：M5 已完成（`v0.5.1`）。

## Global Constraints

- 沿用 M1–M5 計畫的 Global Constraints（Node 26、只支援 macOS、`fnm exec --using=26`）。
- SEA：`node --build-sea`，輸出 `apps/webop/dist/webop`；建置後 `codesign --sign - --force apps/webop/dist/webop`。不上架、不公證。
- 不新增 runtime 相依；esbuild 已是 devDependency。
- 版本：本里程碑結束時 0.6.0；`CHANGELOG.md` 加 `## 0.6.0` 一節（`version.test.ts` 會檢查四處版本一致）。
- NM host 名稱維持 `com.webop.native_host`；包裝腳本維持 `~/.webop/bin/webop-native-host`。
- doctor 的輸出是給人看的中文以外文字一律維持英文（與其他 CLI 訊息一致）；每行開頭 `ok`／`warn`／`FAIL`。exit code：有任何 `FAIL` 為 1，否則 0。
- M6 手動驗收清單放在**獨立檔案** `docs/acceptance/m6-manual-acceptance.md`（使用者要求驗收檔案好找）。

## Review Focus

1. **包裝腳本指向已不存在的執行檔**（搬了 repo、刪了 dist、或像現在指向舊的 node 24 路徑）→ doctor 必須 `FAIL` 並印出腳本實際要執行的命令與「重新執行 `webop install`」。（Task 2 `t_doctor_wrapper_target_missing`）
2. **擴充與 webop 版本不同**（只 rebuild 一邊或沒重新載入擴充）→ doctor `warn`，同時印出兩個版本。（Task 2 `t_doctor_version_mismatch`）
3. **doctor 的 ping 不可開 session**：不得送 `session_open`、工具列徽章數字不變、不得留下分頁群組。（Task 1 `t_ping_opens_no_session`）
4. **兩個 agent 用同一個 client 名稱**（開兩個 opencode）→ 仍是兩個分頁群組、不同顏色、互相不能操作對方分頁。（Task 4 `t_same_client_name_separate_groups`）
5. **socket 檔還在但沒人在聽**（host 被 kill -9、descriptor 的 pid 剛好被重用）→ doctor 對該 profile `FAIL`「socket not accepting connections」，不 crash、不卡住（ping 逾時 2 s）。（Task 2 `t_doctor_dead_socket`）

### Task 2: `webop doctor`

**Files:**
- Create: `apps/webop/src/doctor.ts`、`apps/webop/test/doctor.test.ts`
- Modify: `apps/webop/src/cli.ts`、`apps/webop/src/install.ts`（匯出 `manifestFile`、`wrapperFile`、`HOST_NAME`）

**Interfaces:**
- Consumes: Task 1 的 `ping`／`pong`。
- Produces:
  ```ts
  export type Level = "ok" | "warn" | "FAIL";
  export interface Check { level: Level; title: string; detail?: string }
  export async function doctor(o: { root?: string; browserDirs?: string[]; extensionId: string; pingTimeoutMs?: number }): Promise<Check[]>;
  export function formatChecks(checks: Check[]): string;   // 每行 "<level> <title>"，detail 縮排兩格接在下一行
  ```
- `browserDirs` 預設：`~/Library/Application Support/Google/Chrome`，另外若 `~/Library/Application Support/BraveSoftware/Brave-Browser` 存在也加入（使用者實際用 Brave）。CLI：`webop doctor [--browser-dir <dir>]...`。
- 檢查項目與判定（依序）：

| 項目 | ok | warn | FAIL |
|---|---|---|---|
| host manifest（每個 browserDir） | 存在、`name`、`path` 等於包裝腳本、`allowed_origins` 含 `chrome-extension://<extensionId>/` | 該瀏覽器目錄存在但沒有 manifest（只對非第一個目錄） | 第一個目錄沒有 manifest、JSON 壞掉、`path` 或 `allowed_origins` 不符 |
| 包裝腳本 | 存在、可執行、`exec` 後第一個參數（去引號）是存在的檔案 | — | 不存在、不可執行、或目標檔不存在（detail 印出整行 exec 命令與「re-run `webop install`」） |
| 在線 profile | 至少一個 descriptor 的 pid 活著 | 一個都沒有（「open the browser」）；有 pid 已死的殘留 descriptor（列出檔名） | — |
| 每個在線 profile | ping 成功；title 含 `label (id)`、sessions 數、extension 版本 | `extension_version !== webop_version`（detail：`webop X, extension Y; rebuild and reload the extension`） | 連不上或 `pingTimeoutMs`（預設 2000）內沒回 `pong`：「socket not accepting connections」 |

- `webop doctor` 印出 `formatChecks()`；第一行固定為 `webop <VERSION>`。

- [ ] **Step 1: 寫失敗測試**（`doctor.test.ts`；temp root、temp browserDir；fake host 用 `net.createServer` 回 `pong`，寫法比照 `mcp.test.ts` 的 `fakeHost`）：
  - `t_doctor_all_ok`：`install()` 寫好 manifest 與指向 `process.execPath` 的包裝腳本、一個回 pong（版本相同）的 fake host → 沒有 `warn`／`FAIL`；有一項 title 含 `Work (p1)`。
  - `t_doctor_no_manifest`：沒 install → 第一個 browserDir 的 manifest 為 `FAIL`。
  - `t_doctor_wrong_origin`：manifest 的 `allowed_origins` 是別的 id → `FAIL`。
  - `t_doctor_wrapper_target_missing`：包裝腳本 exec `/nonexistent/webop` → `FAIL`，detail 含 `/nonexistent/webop` 與 `webop install`。
  - `t_doctor_version_mismatch`：pong 的 `extension_version: "0.5.1"`、`webop_version: VERSION` → `warn`，detail 含兩個版本字串。
  - `t_doctor_dead_socket`：descriptor 的 pid 是自己（活著）但 socket 路徑上沒有 server（只寫一個普通檔）→ 該 profile `FAIL`，整體在 `pingTimeoutMs: 300` + 1 s 內回傳。
  - `t_doctor_stale_descriptor`：pid 已死的 descriptor → `warn` 且 detail 含檔名。
  - `t_doctor_exit_code`：用 `spawnSync(process.execPath, [cli, "doctor", "--browser-dir", <空目錄>], {env: {WEBOP_ROOT: tmp}})` → status 1，stdout 第一行 `webop <VERSION>`、含 `FAIL`。
- [ ] **Step 2:** `fnm exec --using=26 node --test apps/webop/test/doctor.test.ts` → FAIL。
- [ ] **Step 3: 實作** `doctor.ts` 與 CLI 子命令（`--browser-dir` 可重複；有給就只用給定的目錄）。
- [ ] **Step 4:** 單元測試全綠、typecheck 無錯。
- [ ] **Step 5: Commit** `feat(webop): doctor checks host manifest, wrapper, live profiles and versions`

**Interfaces:**
- `apps/webop/src/extension-id.ts`：
  ```ts

  export const EXTENSION_ID: string = __WEBOP_EXTENSION_ID__;
  ```
  `build.ts` 以 `extensionIdFromKey(manifest.key)` 算出後用 esbuild `define` 注入；單元測試（直接跑 .ts）時沒有 define → `cli.ts` 經由 `typeof __WEBOP_EXTENSION_ID__ === "undefined"` 時退回讀 `../../extension/manifest.json`（僅開發路徑）。
- `cli.ts` 維持 ESM 與 top-level await；執行期不得再依賴 `import.meta.url` 找檔案（SEA 內沒有旁邊的 manifest.json），只剩開發路徑的 fallback 可用。

  ```
  grok mcp add webop <cmd...> -- mcp
  ```

- `build.ts` 仍只輸出 `dist/webop.mjs`（ESM），SEA 直接用它當入口。
- `build-sea.ts`：寫 `dist/sea-config.json` `{ "main": "dist/webop.mjs", "mainFormat": "module", "output": "dist/webop", "disableExperimentalSEAWarning": true, "useCodeCache": false }`（2026-11-01 已在 Node 26.13 實測：ESM 入口、top-level await、`import.meta` 皆可用） → `node --build-sea dist/sea-config.json` → `codesign --sign - --force dist/webop`。任一步非 0 就以非 0 結束並印出該步的 stderr。
- harness：`launch({ webopCommand?: string[] })`，預設 `[process.execPath, webopBin]`；匯出 `seaBin = apps/webop/dist/webop`。

## 本計畫的判斷（請確認）

1. **SEA 直接用 ESM 入口**（`mainFormat: "module"`，已實測可用），不另產 CJS；擴充 ID 改在建置時寫入，因為 SEA 執行檔旁邊沒有 manifest.json。
2. **doctor 透過新增的 `ping` 查 host**，而不是開一個真的 session（開 session 會改徽章數字、可能建分頁群組）。
3. **doctor 預設也檢查 Brave 的 NM 目錄**（只在該目錄存在時，且缺 manifest 只算 `warn`），因為實際使用的是 Brave；規格 v1 只驗 Chrome，這是額外的方便，不改 install 的預設目錄。
4. **兩個 agent 同時操作預期現有架構已滿足**，Task 4 以 e2e 證明；只有測試失敗才改程式。
5. **系統提示範本搬到 `docs/agents/README.md`**，opencode 與 grok 共用一份。
6. **M6 驗收清單用獨立檔案** `docs/acceptance/m6-manual-acceptance.md`。
