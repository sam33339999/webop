# webop M4（授權完整版）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 M3 的「白名單一律放行」換成規格 §4.4 的完整授權：read / act / javascript 分級、擴充 popup 詢問、本次／永久授權、拒絕清單、設定頁、動作前重驗、停止鈕；並收掉 M1–M3 延後的穩定性項目。

**Architecture:** 純判斷邏輯（工具 → 權限等級、授權表 → allow/deny/ask）放 `packages/core/src/grants.ts`。擴充端 `permissions.ts` 管儲存與決策，`prompt.ts` 開 popup 視窗等使用者回答；`tools.ts` 的每個入口改呼叫 `requireAccess()`。詢問期間擴充送 `tool_pending` 讓 host／mcp 延長逾時，呼叫的 50 秒期限從授權通過後才起算。停止鈕在覆蓋層，經 content script 通知 SW 以 session 為單位中止。

**Tech Stack:** 沿用 M1–M3：Node 26、TypeScript（type stripping）、pnpm workspaces、esbuild、`@modelcontextprotocol/sdk` 1.32、zod 4、tldts 7、`node:test`、Playwright 1.64 Chromium。

**Spec:** `docs/superpowers/specs/2026-10-31-webop-design.md`（§4.4 授權、§4.6 覆蓋層、§6 M4 列）；行為細節 `ANALYSIS.md` §6。前一份計畫：`docs/superpowers/plans/2026-10-31-webop-m1-m3.md`（已合併進 `main`）。

## Global Constraints

- 沿用 M1–M3 計畫的 Global Constraints 全部條目（Node `>=26`、erasable TS、`node:test`、core 不 import `node:*`／`chrome.*`、host 名稱 `com.webop.native_host`、`~/.webop/run/` 權限、`browser_` 前綴、截圖預算、click 時序、e2e 只用 Playwright Chromium + 暫存 profile、參考資料夾不得 import／複製）。
- 錯誤碼只能用 `packages/core/src/protocol.ts` 的 `ErrorCode`；本計畫開始實際使用 `permission_required`、`security_check_failed`、`stopped_by_user`。
- 權限等級：`read`（`navigate`、`tabs_create`、`read_page`、`computer` 的 `screenshot`）、`act`（`computer` 其餘 action；隱含 `read`）、`javascript`（不被 `act` 隱含；需設定頁全域開關**且**該網域授權）。
- 授權單位：`siteOf()`（eTLD+1，private suffix 各自獨立）。非 http(s) 一律拒絕。
- 詢問逾時：**60 000 ms** 未回應 = 拒絕。關閉 popup 視窗 = 拒絕。
- 授權範圍：`once`（本 session 有效，存 `chrome.storage.session`）、`always`（存 `chrome.storage.local`）。
- 拒絕清單內網域：直接 `permission_denied`，不跳詢問。
- popup 由擴充自己開（`chrome.windows.create({type: "popup"})`），**不在頁面內畫詢問 UI**；popup 內容（截圖、點擊位置）只給使用者看，絕不回傳 agent。
- 停止鈕：z-index `2147483647`；只接受 `event.isTrusted` 的點擊。
- 呼叫期限 `callDeadlineMs` 50 000、CDP send 20 000、探測 2 000（N1 的值不變）。
- storage key：`webop.grants`（永久）、`webop.deny`、`webop.js_enabled`、`webop.session_grants`（session storage）；M3 的 `webop.allow` 只讀一次做遷移後刪除。

## Review Focus

1. **agent 在詢問期間收到 MCP 60 秒逾時，但使用者稍後按了允許** → 不得在 agent 已收到失敗後才執行動作；詢問期間逾時必須被延長，或詢問被取消並回 `permission_denied`。（Task 4 測試 `t_pending_extends_timeout`、`t_answer_after_cancel_noop`）
2. **同一 session 對同一網域並行送三個呼叫** → 只跳一個 popup，三個呼叫共用同一個答案。（Task 3 測試 `t_dedupe`）
3. **頁面腳本偽造點擊停止鈕或偽造詢問結果** → 停止鈕忽略 `isTrusted=false`；popup 回答只接受來自擴充自己 `prompt.html` 的訊息。（Task 3 `t_answer_sender_checked`、Task 6 `t_stop_untrusted_ignored`）
4. **從 M3 升級的使用者** → `webop.allow` 裡的網域自動變成永久 `act` 授權，不會一升級就全部跳詢問。（Task 2 `t_migrate_allow`）
5. **動作進行中分頁被導向別的網域（解析 ref 的期間）** → 送出輸入前重驗，回 `security_check_failed` 且訊息含「Not performed」。（Task 5 `t_site_changed_before_input`）

  export async function requireAccess(o: {
    session_id: string; client_name: string; url: string; level: Level;
    tabId?: number; marker?: { x: number; y: number }; signal?: AbortSignal;
  }): Promise<void>;   // allow → return；deny → permission_denied；ask → ask() 後依答案 grant 或 permission_denied

- 規則：

  2. `read_page`、`screenshot`：對分頁目前網址 `requireAccess(read)`。

  5. `tabs_create` 被導向到需詢問或被拒的網域：沿用 M3 規則關掉分頁，回 `permission_required`／`permission_denied`。

### Task 6: 停止鈕、偵錯列取消語意、badge

**Files:**
- Modify: `apps/extension/src/overlay.ts`、`apps/extension/src/sw/sessions.ts`、`apps/extension/src/sw/tools.ts`、`apps/extension/src/sw/cdp.ts`、`apps/extension/manifest.json`（加 `"action": {}`）

**Interfaces:**
- Produces:
  ```ts
  export async function stopSession(session_id: string): Promise<void>; // sessions.ts
  export function stopEpoch(session_id: string): number;                // 每次 stop +1
  ```
- 停止鈕：覆蓋層右下角固定按鈕，只在 session 擁有的分頁、glow 開著時顯示；點擊（`isTrusted`）送 `{type:"webop:stop"}`；SW 以 `sender.tab.id` 找擁有該分頁的 session 執行 `stopSession`。
- `stopSession`：epoch +1、abort 該 session 進行中的 `ask()`、detach 該 session 所有分頁、`revokeSessionGrants`。session 不關閉。
- `dispatch` 在收到呼叫時記下 epoch；`withTab` 輪到時、`perform` 前、回傳前發現 epoch 變了 → `stopped_by_user`（`Not performed: the user pressed stop.`；已送輸入者沿用「may have been partially or fully performed」前綴）。
- 偵錯列「取消」（`canceled_by_user`）：視同對擁有該分頁的 session 按停止；另外該分頁**下一次**呼叫回一次 `detached_by_user`（`Not performed: the user stopped debugging this tab; retry to re-attach.`），之後重試正常 attach。
- badge：`chrome.action.setBadgeText({text: n>0 ? String(n) : ""})`，n = host 開啟的 session 數；session 開／關時更新。

- [ ] **Step 1: 寫失敗 e2e**（`stop.spec.ts`）：

## 本計畫的判斷（請確認）

1. **詢問是「阻塞等待」**：工具呼叫會等使用者回答（最多 60 秒），期間用 `tool_pending` 延長 MCP 端逾時，agent 不需要重試。代價：多一組協定訊息；若 opencode 自己的工具逾時比 70 秒短，仍可能先放棄（Task 4 的取消機制保證此時動作不會晚到）。
2. **「導向後才發現未授權」回 `permission_required` 並在背景跳詢問**，不阻塞；其他情況（導航前、動作前）阻塞詢問。
3. **M3 白名單自動轉成永久 `act` 授權**，升級後不會突然全部跳詢問。
4. **偵錯列「取消」= 停止**：撤銷本次授權，且該分頁下一次呼叫回一次 `detached_by_user`（回應手動驗收第 9 項）。
5. **`browser_javascript` 工具本身放 M5**；M4 只做 `javascript` 等級、全域開關與詢問。
6. **content script 改成只注入 session 擁有的分頁**（M3 是全部網站）。
