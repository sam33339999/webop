# webop M5（讀取工具與多 profile）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 補齊規格 §4.5 剩下的工具（`browser_get_page_text`、`browser_form_input`、`computer` 的 `zoom`、`browser_javascript`），並讓 agent 在多個 Chrome profile 同時在線時能列出、選定並只操作指定 profile；截圖預算可由 CLI 參數依模型調整。

**Architecture:** 新讀取／填表工具沿用 M4 的 `requireAccess()` 與 per-tab 佇列，頁面端邏輯放 content script（`ax.ts` 增訊息，或新 `text.ts`）。多 profile 全在 `webop mcp` 端處理：profile 工具不轉送給擴充；mcp 依 `--profile`／`browser_profile_select`／在線數量決定連哪個 host socket。profile 顯示名稱由擴充提供，可在設定頁改名，透過新訊息同步到 host 描述檔。

**Tech Stack:** 同 M4。

**Spec:** `docs/superpowers/specs/2026-10-31-webop-design.md`（§4.2 多 profile、§4.5 工具集、§6 M5 列）；`ANALYSIS.md` §3–5。前置：`docs/superpowers/plans/2026-10-31-webop-m4.md` 已完成（`requireAccess`、`Level`、`tool_pending`）。

## Global Constraints

- 沿用 M1–M3 與 M4 計畫的 Global Constraints。
- 新 MCP 工具名：`browser_get_page_text`、`browser_form_input`、`browser_javascript`、`browser_profiles_list`、`browser_profile_select`；`browser_computer` 的 action 加 `zoom`。
- 權限：`get_page_text`、`zoom` = `read`；`form_input` = `act`；`javascript` = `javascript`（全域開關 + 網域授權，見 M4）。
- 文字上限：`get_page_text` 預設 `max_chars` 50 000；`javascript` 結果上限 50 000 字元，超過截斷並註明 `…(truncated)`。
- 動作類（`form_input`）完成後附截圖（同 `computer`，含尺寸提示 text block）。
- profile 顯示名稱：`chrome.identity.getProfileUserInfo({accountStatus:"ANY"})` 的 email；空字串時 `profile-<profile_id 前 6 碼>`；設定頁可改名（存 `webop.profile_label`，非空時優先）。
- `--profile <x>`：先比對 `profile_id` 完全相同，否則比對 label（不分大小寫、完全相同）；比對到 0 個 → `not_connected`（列出在線 profile）；多個 → `profile_required`。
- 截圖預算 CLI：`webop mcp --image-max-px <n> --image-max-tokens <n> --px-per-token <n>`，皆為正整數；未給沿用預設 1568 / 1568 / 28。

## Review Focus

1. **opencode 已連上一個 profile 後，使用者又開了第二個 profile**（手動驗收 M3 第 12 項）→ 未明確選定（沒有 `--profile`、沒呼叫過 select）時，下一次工具呼叫回 `profile_required` 並列出兩者；選定後不再問。（Task 2 `t_second_profile_mid_session`）
2. **選定的 profile 關掉了**（Chrome 視窗關閉、host 退出）→ 回 `not_connected`，訊息點名該 profile；**不得**自動改連另一個 profile。（Task 2 `t_bound_profile_gone`）
3. **`form_input` 對 password 欄位** → 可以填，但回傳文字不得包含所填的值。（Task 4 `t_form_input_password_not_echoed`）
4. **`get_page_text` 在被導向未授權網域後呼叫** → 與 `read_page` 相同回 `permission_required`，不回文字。（Task 3 `t_page_text_after_redirect`）
5. **`zoom` 區域超出截圖或寬高為 0** → `invalid_args` / `oob`，不 crash、不更新座標框架。（Task 5 `t_zoom_bad_region`）

### Task 4: `browser_form_input`

**Files:**

**Interfaces:**
- 工具參數：`{ tab_id: number; ref: string; value: string | number | boolean }`。
- content script 訊息 `{type:"webop:form_input", ref, value}` → `{ ok: true; kind: string } | { error: "stale_ref" | "unsupported" | "bad_value"; message: string }`。
- 規則：
  - `input`（text 類、number、email、search、url、tel、password、date…）、`textarea`：以原型的 `value` setter 設值，依序觸發 `input`、`change`（`bubbles: true`）。

  - `checkbox`／`radio`：`value` 必須是 boolean，否則 `bad_value`；設 `checked` 後觸發 `input`、`change`、`click` 不觸發。
  - `disabled`／`readonly` → `unsupported`；其他元素 → `unsupported`。
  - 授權：`act`；送出前做跨網站 frame 檢查與 M4 的「網址未變」重驗；完成後附截圖。
  - 回傳文字 `Set <kind> <ref>`；**不含**所填的值。
- 錯誤對應：`stale_ref` → `stale_ref`；`unsupported`／`bad_value` → `invalid_args`。

- [ ] **Step 1: 寫失敗 e2e**：

## 本計畫的判斷（請確認）

1. **未明確選 profile 時，每次呼叫都檢查在線數量**；中途多開 profile 會回 `profile_required`，直到 agent select（回應手動驗收第 12 項）。已用 `--profile` 或 select 綁定的不受影響。
2. **綁定的 profile 消失不自動換**，回 `not_connected`。
3. **截圖預算 CLI 參數放在 M5**（規格 §4.5 有要求，但里程碑表沒列）。
4. **`browser_javascript` 放在 M5**，依賴 M4 的 `javascript` 等級。
5. **`form_input` 回傳不含所填的值**，避免密碼等內容出現在 agent 對話紀錄。
6. **`get_page_text` 的主內容擷取**用簡單規則（main → role=main → 最長 article → body，去掉導覽列等），不引入 Readability 之類的函式庫。
